# Build & run guide

This app is source-complete but was authored in an environment **without a Flutter SDK**. Run the
steps below on a machine with Flutter installed. Nothing in `openjarvis/` is required to build the
client — only to serve it.

## 1. Install Flutter

| Platform | Notes |
|---|---|
| All | [flutter.dev/docs/get-started/install](https://docs.flutter.dev/get-started/install) — stable channel, Dart 3.4+ |
| Linux | `sudo snap install flutter --classic` then `flutter init`, or unpack the tarball and add `flutter/bin` to `PATH` |
| macOS | `brew install --cask flutter` |
| Windows | Download the SDK zip, extract to `C:\src\flutter`, add `C:\src\flutter\bin` to `PATH` |

Verify:

```bash
flutter --version
flutter doctor -v
```

`flutter doctor` tells you exactly which extra pieces you need:

- **Android**: Android Studio (SDK Platform 34+, build-tools), JDK 17, accept licenses with
  `flutter doctor --android-licenses`.
- **iOS/macOS**: Xcode (macOS only), `sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer`,
  CocoaPods (`sudo gem install cocoapods`).
- **Web**: Chrome/Edge for `-d chrome`; no extra SDK.
- **Windows**: Visual Studio 2022 with the *Desktop development with C++* workload.
- **Linux**: `clang`, `cmake`, `ninja`, `libgtk-3-dev`, `liblzma-dev`.

## 2. Add platform folders

The `aira/` folder contains `lib/`, `test/` and the pubspec — platform runner folders are
generated by Flutter itself:

```bash
cd aira
flutter create --project-name aira --org com.openjarvis \
  --platforms=android,ios,web,windows,macos,linux .
flutter pub get
flutter analyze
flutter test
```

`flutter create .` only adds missing platform folders; it does not replace your Dart sources.

**Identity used by this project**

| Field | Value |
|---|---|
| App name | **AIRA** |
| Dart package | `aira` |
| Android `applicationId` | `com.openjarvis.aira` |
| iOS `PRODUCT_BUNDLE_IDENTIFIER` | `com.openjarvis.aira` |
| macOS bundle identifier | `com.openjarvis.aira` |
| Linux app id | `com.openjarvis.aira` |

The command above already generates those platform IDs. After generation, set the visible label
to **AIRA** (not the folder name):

- Android: `android/app/src/main/AndroidManifest.xml` → `<application android:label="AIRA">`
- iOS: `ios/Runner/Info.plist` → `CFBundleDisplayName` = `AIRA`
- macOS: `macos/Runner/Info.plist` → `CFBundleName` = `AIRA`
- Web: `web/index.html` → `<title>AIRA</title>` and `manifest.json` → `"name": "AIRA"`

## 3. Run and build

```bash
# Development
flutter run -d chrome          # web
flutter run -d android         # connected phone / emulator
flutter run -d windows         # or macos / linux

# Release artifacts
flutter build apk --release                       # Android (or: flutter build appbundle)
flutter build ipa --release                       # iOS (needs signing)
flutter build web --release                       # web/ directory
flutter build windows --release                   # Windows
flutter build macos --release                     # macOS
flutter build linux --release                     # Linux
```

Web note: serve the built `build/web` over HTTPS (or `localhost`) — microphone access requires a
secure context. The OpenJarvis server must allow your web origin via `server.cors_origins`.

## 4. Start the OpenJarvis server

OpenJarvis needs Python **3.11–3.13** and `uv`. The repository root (one level up from `aira/`)
is the backend checkout.

```bash
cd ..
uv venv --python 3.12 .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
uv pip install -e ".[server,inference-cloud,speech,agents-openai]"
```

For the AIRA setup described in this repo (Hermes Agent as the main runtime,
`gemini-3.1-pro-preview` via OmniRoute, OpenAI Agents SDK sub-agent), copy the
ready-made preset — it already enables memory, voice and scheduling:

```bash
cp configs/openjarvis/examples/aira-hermes-gemini.toml ~/.openjarvis/config.toml
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
hermes mcp add openjarvis_subagent --command "$(command -v python)" --args -m openjarvis.subagents.mcp_server
```

Full setup details: `docs/user-guide/aira-hermes-gemini.md`.

Alternatively, start from the generic chat preset:

```bash
jarvis init --preset chat-simple --force
```

Enable the pieces the app uses (edit `~/.openjarvis/config.toml`):

```toml
[engine]
default = "cloud"

[intelligence]
default_model = "omni/gpt-4o-mini"   # any model alias your OmniRoute serves

[agent]
default_agent = "orchestrator"        # tool-using agent; "simple" also works

[scheduler]
enabled = true

[server]
host = "127.0.0.1"
port = 8000
cors_origins = [
  "http://localhost:5173",
  "http://localhost:8080",
  "http://tauri.localhost",
  "https://tauri.localhost",
]

[speech]
backend = "openai"
tts_backend = "openai_tts"
language = "bn"
```

> Model names are examples. With `OPENAI_BASE_URL` set, this fork's `CloudEngine.can_serve()`
> accepts arbitrary names, so use exactly the alias OmniRoute exposes.

### OmniRoute connection

```bash
export OPENAI_BASE_URL="http://127.0.0.1:3141/v1"   # your OmniRoute base URL
export OPENAI_API_KEY="sk-..."                      # OmniRoute key (never ship it in the app)
export OPENJARVIS_API_KEY="aira-client-key"        # key YOU enter in the Flutter app
# Only for the Hermes preset with the sub-agent enabled:
export OPENAI_SUBAGENT_API_KEY="sk-..."             # may be the same OmniRoute key
```

Start it:

```bash
jarvis serve --host 127.0.0.1 --port 8000
# health check:
curl http://127.0.0.1:8000/health
```

If you run the Flutter app on a phone or another machine, use the server's LAN address in
Settings and bind the server accordingly (`--host 0.0.0.0`) **only on a trusted network**, with
`api_key` configured in OpenJarvis.

## 5. API surface used by the app

| Feature | Endpoint |
|---|---|
| Chat | `POST /v1/chat/completions` (`stream: true`, SSE chunks + `data: [DONE]`) |
| Models | `GET /v1/models` |
| Health | `GET /health` |
| Speech | `POST /v1/speech/transcribe` (multipart `file`, optional `language`), `POST /v1/speech/synthesize` (`{text, voice_id?, speed?}` → WAV) |
| Memory | `POST /v1/memory/search`, `POST /v1/memory/store`, `GET /v1/memory/stats`, `GET /v1/memory/config` |
| Schedule | `GET/POST /v1/managed-agents`, `PATCH/DELETE /v1/managed-agents/{id}`, `POST /v1/managed-agents/{id}/pause|resume` |

## 6. Known limitations

- Speech capture uses the `record` plugin; browser support depends on `MediaRecorder` (Chrome and
  Edge are fine, Safari is limited). Voice features degrade gracefully with a clear message.
- Scheduled agents run on the **server**, so the server must stay online. The app only manages them.
- The server's built-in tool set is powerful; keep `security.enabled = true` and grant only the
  tools you actually need via `tools.enabled`.
- Desktop `flutter build` needs a GUI toolchain; CI can run `flutter test` headlessly anywhere.
